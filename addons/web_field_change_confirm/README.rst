This module shows a confirmation dialog when you save a form in which a
field with the ``confirm_change`` attribute has changed. The dialog
lists these fields with their old and new values.

**Table of contents**

.. contents::
   :local:

Configuration
=============

Add the ``confirm_change`` attribute to a field of a form view. Its
value is a Python expression, like ``readonly``. The dialog opens only
when the expression is true.

.. code:: xml

   <!-- Always ask -->
   <field name="partner_id" confirm_change="1"/>

   <!-- Ask only on confirmed orders -->
   <field name="partner_id" confirm_change="state == 'sale'"/>

In an inherited view:

.. code:: xml

   <xpath expr="//field[@name='partner_id']" position="attributes">
       <attribute name="confirm_change">state == 'sale'</attribute>
   </xpath>

Usage
=====

To use this module, you need to:

1. Open a form with a field that has the ``confirm_change`` attribute.
2. Change the field, then save the record or leave it.
3. In the dialog, click **Save** to save the record, or **Keep editing**
   to go back to the form without saving.

When such a field has changed, switching to another browser tab doesn't
save the record, and closing or reloading the tab asks for confirmation
before leaving the page.

Known issues / Roadmap
======================

- Only form views show the dialog. Inline editing in list views and drag
  and drop in kanban views save without confirmation.
- The attribute is ignored on one2many and many2many fields.
- Creating a record doesn't show the dialog.
- For binary, HTML, JSON and properties fields, the dialog shows
  "Modified" instead of the values.
- Imports, RPC calls and server actions don't show the dialog.
