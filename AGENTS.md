# AGENTS.md

**basaltbytes/odoo-addons** — generic, reusable Odoo 19 Community addons published by
basaltbytes. Every addon here must stay client-agnostic: no customer names, data or
workflows. `CLAUDE.md` is a symlink to this file.

## Layout

- `addons/<addon>/` — one folder per addon. Odoo discovers manifests one level below
  `addons/`, which is the only folder mounted into the Odoo container.
- Authored: `web_field_change_confirm`, `web_module_test_harness`. Vendored, excluded
  from every linter and formatter: `odoo_test_xmlrunner`, a 19.0 port of OCA's 18.0
  addon (OCA/server-tools); keep changes to what the port needs. A new vendored addon
  joins the exclude lists in `.pre-commit-config.yaml`, `.ruff.toml`, `.oxlintrc.json`,
  `.oxfmtrc.json` and `scripts/gen-addon-readmes.mjs`.
- `scaffold-template/` — `odoo-bin scaffold -t` template for a new addon.
- `types/` — hand-written type overlays; `types/odoo-upstream/` is synced by
  `pnpm sync:odoo-types`, never committed.

Commands live in `package.json` scripts. Run them from the repo root with pnpm; keep the
pnpm (`packageManager`), Node (`.node-version`) and pyenv (`.python-version`) pins.
`pnpm-workspace.yaml` makes pnpm resolve only versions at least 3 days old, the same
gate as Dependabot's cooldown. A plain `pnpm install` keeps the entries already locked;
to re-resolve under the gate, delete `node_modules` and `pnpm-lock.yaml` first.

## Definition of done

A behavior change lands in one PR with:

1. **Tests** — Python in `tests/`, imported from `tests/__init__.py` (an unimported test
   never runs and CI passes vacuously); web client code in Hoot under `static/tests/`.
2. **Readme fragments** — `readme/*.md`, in English, `##` for top-level subsections.
   `README.rst` and `static/description/index.html` are generated by `pnpm gen:readme`
   (the pre-commit hook runs it) and committed; CI fails on drift. Never add an
   addon-level `README.md`.
3. **Translations** — every user-facing string, JS `_t()` and static OWL/QWeb text
   alike, gets its entry in both `i18n/<addon>.pot` and `i18n/fr.po`.
4. **Changelog** — a line under `## [Unreleased]` in `CHANGELOG.md`.

## Coding standards

- `checkJs` type-checks the JavaScript: JSDoc anything that would degrade to `any`
  (public methods, cross-file values, parser outputs, service interfaces) with the real
  runtime contract. Missing Odoo declarations go in `types/`. Validate with
  `pnpm typecheck`; `tsconfig.json` is the editor config, not a gate.
- Manifest assets: every new `static/src/` file is covered by the addon's
  `__manifest__.py` `assets` in the same diff — typecheck cannot see a missing entry,
  and the file then loads zero bytes at runtime.
- Prefer Odoo's extension seams — registries, controller hooks such as
  `onWillSaveRecord`, `js_class` — over patches. When a patch is the only global route,
  patch prototype methods, call `super`, and name every private web-client API it reads
  in a comment backed by a test that breaks when that API changes.
- Owl hands components reactive proxies: compare records with `toRaw(a) === toRaw(b)`.
- Custom widgets follow the record like the surrounding UI: declare real
  `fieldDependencies` and refresh after header actions and dialog closes. Data stale
  until F5 is a bug.
- `useService("orm")` is component-bound: a call in flight at unmount never settles.
  Code that must outlive the component uses `env.services.orm`.
- Python: framework idioms (recordsets, constraints, `UserError`/`ValidationError`),
  thin workflow code, business rules named and tested. Docstring entry points with a
  one-line imperative summary.
- Addon and field names come from the domain, never from a customer or a vendor prefix.

## Testing

- Odoo tests run in an
  [oad](https://www.npmjs.com/package/@basaltbytes/odoo-agentic-dev) stack configured by
  `odoo-agentic-dev.config.ts`: `pnpm dev:setup` once per checkout, then
  `pnpm test:odoo` (every suite) or `pnpm test:hoot` (browser suites only). Iterate with
  a scoped tag (`pnpm exec oad test --tags /<addon>:<TestClass>`); CI runs the full
  profile. `oad test` recreates the test database; stop a running stack with
  `pnpm dev:down` first.
- Failing tests land as JUnit XML in `addons/test_results/`; read them with
  `pnpm test:report`.
- Hoot suites run per addon through `web_module_test_harness`: declare a
  `<addon>.assets_unit_tests` bundle and subclass `ModuleHootCase` with
  `module_name = "<addon>"` (see `web_field_change_confirm/tests/test_js.py`). The addon
  does not depend on the harness; the test stack installs it.
- A test run that reports `0 tests`, or Hoot suites skipped for a missing
  `websocket-client`, is a failure to investigate, not a pass.
- A flaky test is root-caused and fixed when it appears.

## Translations

- Add strings additively to both `fr.po` and the `.pot`; never regenerate a whole POT
  over a database that lacks the addon's data. `pnpm i18n:update <addon> [lang]` exports
  from the oad database.
- Every entry keeps its `#:` reference line: without it Odoo 19 silently skips the
  translation.
- `.po`/`.pot` merges use the `odoo-po` union driver (`.gitattributes`, configured by
  `pnpm install`); `pnpm i18n:format` canonicalizes afterwards.

## Branching

Branch from `main` and open PRs against `main`.
